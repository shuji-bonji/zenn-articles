## はじめに

RxJSは強力なリアクティブプログラミングライブラリですが、学習曲線が急であることでも知られています。

- 100以上のオペレータの中から適切なものを選ぶ難しさ
- `switchMap` vs `mergeMap` vs `concatMap` の使い分け
- ネストした `subscribe` などのアンチパターンに気づきにくい
- マーブル図の理解

これらの課題に対して、AIアシスタントが適切にサポートできれば、開発体験が大きく向上するのではないか？そう考えて、RxJS特化のMCPサーバーを作りました。

## 作ったもの

**@shuji-bonji/rxjs-mcp** - RxJSの学習・開発を支援するMCPサーバーです。

https://www.npmjs.com/package/@shuji-bonji/rxjs-mcp

### 主な機能

| 機能 | 説明 |
|:---|:---|
| アンチパターン検出 | ネストしたsubscribe、takeUntil漏れなどを指摘 |
| オペレータ提案 | ユースケースに応じた適切なオペレータを提案 |
| マーブル図の例示 | オペレータの動作をマーブル記法で説明 |
| ドキュメント検索 | RxJSの公式ドキュメントを文脈に応じて検索 |

## 使用例

### 例1: アンチパターンの検出

以下のようなコードをAIに見せると、問題点を指摘してくれます。

```typescript
// ❌ ネストしたsubscribe（アンチパターン）
from(api.getUser(id)).subscribe(user => {
  from(api.getOrders(user.id)).subscribe(orders => {
    console.log(user.name, orders.length);
  });
});
```

AIの指摘：

> このコードには「ネストしたsubscribe」というアンチパターンがあります。
> `switchMap` を使ってフラットに書き換えることをお勧めします。

```typescript
// ✅ 改善版
from(api.getUser(id)).pipe(
  switchMap(user => from(api.getOrders(user.id)).pipe(
    map(orders => ({ user, orders }))
  ))
).subscribe(({ user, orders }) => {
  console.log(user.name, orders.length);
});
```

### 例2: オペレータの選択支援

「検索ボックスの入力を処理したい。入力中は待機して、最新の入力だけを処理したい」と相談すると：

> この要件には以下の組み合わせが最適です：
> - `debounceTime`: 入力が落ち着くまで待機
> - `distinctUntilChanged`: 同じ値の重複を除去
> - `switchMap`: 最新のリクエストのみを処理（古いリクエストはキャンセル）

```typescript
searchInput$.pipe(
  debounceTime(300),
  distinctUntilChanged(),
  switchMap(term => searchApi(term))
).subscribe(results => {
  // 検索結果を表示
});
```

### 例3: Higher-Order Mapping Operatorの使い分け

「`switchMap`、`mergeMap`、`concatMap`、`exhaustMap` の違いがわからない」という質問に対して、マーブル図を用いて説明：

```
入力:     --a------b------c--|

switchMap (最新のみ、前のはキャンセル):
          --x-x-x--y-y-y--z-z-z--|

mergeMap (全部並列実行):
          --x-x-x--y-y-y--z-z-z--|
                   x-x-x--y-y-y--|
                          x-x-x--|

concatMap (順番に直列実行):
          --x-x-x--x-x-x--x-x-x--|
                         (bとcは待機)

exhaustMap (処理中は新規を無視):
          --x-x-x-----------z-z-z--|
                   (bは無視)
```

## Angular MCPとの併用

Angular開発では `@angular/cli` MCPと併用することで、より強力なサポートが得られます。

```json
{
  "mcpServers": {
    "angular": {
      "command": "npx",
      "args": ["-y", "@angular/cli", "mcp"]
    },
    "rxjs": {
      "command": "npx",
      "args": ["-y", "@shuji-bonji/rxjs-mcp"]
    }
  }
}
```

| MCP | 得意領域 |
|:---|:---|
| `@angular/cli` | コンポーネント生成、Angular構文、Signals、ルーティング |
| `@shuji-bonji/rxjs-mcp` | RxJSオペレータ選択、アンチパターン検出、ストリーム設計 |

AIがAngularの構造とRxJSのパターンの両方を理解した上で、コードレビューや提案をしてくれます。

## 検出できるアンチパターン

現在、以下のようなアンチパターンを検出・指摘できます：

### 重大度: 高
- **ネストしたsubscribe**: `subscribe` の中で `subscribe` を呼ぶ
- **takeUntil漏れ**: コンポーネント破棄時のメモリリーク
- **エラーハンドリングの欠落**: `catchError` のない危険なストリーム

### 重大度: 中
- **Subjectの乱用**: `scan` や `withLatestFrom` で代替可能なケース
- **不適切なオペレータ選択**: `switchMap` を使うべき場所で `mergeMap` など
- **toPromiseの使用**: 非推奨API

### 重大度: 低
- **複数subscribe**: `shareReplay` 等で最適化可能
- **過度なany型**: 型安全性の喪失
