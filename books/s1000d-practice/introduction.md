この本は、「[S1000D入門 — 中心概念を仕様に沿って読む](https://zenn.dev/shuji_bonji/books/s1000d-intro)」を読み終えた人が、実際のデータモジュール（DM）を読み、確かめ、作れるようになるための続編です。入門が概念を説明したのに対して、この本は XML の要素と属性を 1 つずつ取り上げて、自作のデータで手を動かします。

## 読者

想定している読者は次の 2 つの立場の人です。この本は 2 つを分けずに書いています。

- S1000D の DM を作り、直し、納める人
- S1000D の XML を処理するコードを書く人

2 つの立場で必要になる S1000D の知識はほぼ同じです。違いが出るのは、検証の内部処理（XSD、XPath、正規表現）などの限られた部分です。その部分は各章の末尾の「実装するときの注意」にまとめました。DM を作るだけの人はこの節を読み飛ばして構いません。

商用の CSDB 製品を持たない読者も想定しています。その場合は、作る立場の人でも、検証やファイルの管理を自分で行うことになります。

## この本の構成

副題の「読み、確かめ、作る」が、そのまま章の並びです。1 件の DM を読み、確かめ、作り、改版するまでを先に一通り行います。その後で、複数の DM にまたがる内容（適用性、パブリケーションモジュール、CSDB 全体の管理）を扱います。

| 段階 | 章 | 扱う内容 |
| --- | --- | --- |
| 準備 | 1〜2 | 仕様パッケージと例の CSDB の用意 |
| 読む | 3〜7 | ファイル名、識別・状態の部分、説明・手順・プロセス・故障探求の DM、参照と図 |
| 確かめる | 8〜10 | DM と XSD・BREX の関係、XSD による検証、BREX による検査、結果の見方 |
| 作る | 11〜12 | DM の作成、作業中の版での修正と改版 |
| まとめる | 13〜15 | 適用性、パブリケーションモジュール、データ管理リストとの照合 |
| 付録 | A・B | レビューの指摘のコメント化、多言語版の作成 |

各章は次の順で書いています。

1. **仕様の規定** — S1000D が何を決めているか。仕様書の章（Chap）と段落（Para）の番号を添えます。
2. **例** — 自作のデータでの XML。
3. **確かめ方** — 書いたものが決まりに合っているかをどう確かめるか。
4. **実装するときの注意** — コードを書く人に向けた内容。

各章の「確かめ方」で見る観点は、「[CSDB をフォルダーと Git で持つ](https://zenn.dev/shuji_bonji/books/s1000d-practice/viewer/csdb-and-dml)」の「納める前に確かめること」に一覧にしています。

## 実践データ

実践例として、架空の指定席券売機（モデル識別コード `KENBAIKI`）の CSDB を使います。S1000D の公式サンプルではなく、著者が作ったデータです。XML ファイルは 18 個あります。

| 種類 | 件数 | 内容 |
| --- | --- | --- |
| 説明の DM（情報コード `040`） | 2 | 券売機の概要、用語 |
| 手順の DM（`520`） | 10 | きっぷを買う手順（4 件）、前面扉を開ける、紙幣ユニットを取り出す（3 つの版と英語版で 5 ファイル） |
| プロセスの DM（`130`） | 1 | きっぷを買う手順の流れ |
| 故障探求の DM（`411`） | 1 | きっぷが出てこない |
| BREX の DM（`022`） | 2 | 券売機のプロジェクトの BREX と、その上位の組織の BREX |
| パブリケーションモジュール | 1 | 操作マニュアルの目次 |
| コメント | 1 | レビューの指摘 |

このほかに、DM が指す図のファイル（ICN）が 6 個あります。券売機の画面の図（PNG）が 4 つ、前面扉の図（PNG）が 1 つ、前面扉の 3D モデル（STEP）が 1 つです。

実践データは、GitHub の [shuji-bonji/s1000d-examples](https://github.com/shuji-bonji/s1000d-examples) にあります。ライセンスは CC BY 4.0 です。

| フォルダー | 内容 |
| --- | --- |
| `kenbaiki/csdb/` | 上の表の 18 個の XML ファイルと、6 個の図のファイル |
| `kenbaiki/chapters/` | 章ごとに、足したファイルと直したファイル。フォルダー名の先頭が章番号です |

:::message
`KENBAIKI` というモデル識別コードと、`K0001`・`K0002` という企業コードは、例のための架空の値です。実際に納めるデータでは、モデル識別コードの登録や、企業コード（CAGE コード）の取得が前提になります。
:::

## 学習に必要なもの

### 必要なファイル

| ファイル | 入手先 | 使う章 |
| --- | --- | --- |
| S1000D Issue 7 の仕様パッケージ（仕様書の PDF、XML スキーマ、既定 BREX など） | 公式の[ダウンロードサイト](https://users.s1000d.org/)。読者が各自で入手する | 「仕様パッケージを用意する」で用意し、本全体で使う |
| 実践データ（券売機の CSDB） | GitHub の [shuji-bonji/s1000d-examples](https://github.com/shuji-bonji/s1000d-examples)（上の「実践データ」） | 本全体 |

仕様パッケージを各自で入手する理由と、展開した後のフォルダーの使い方は、「[仕様パッケージを用意する](https://zenn.dev/shuji_bonji/books/s1000d-practice/viewer/spec-package)」で説明します。

### 調べるときに使うページ

要素や属性の定義と、値の一覧は、この本には書いていません。S1000D の Issue が変わると、内容が変わるためです。調べるときは次のページを使います。

| ページ | 内容 | 提供元 |
| --- | --- | --- |
| [S1000D Data Dictionaries](https://s1000d.org/?page_id=1003) | 要素と属性の定義。Issue 4.0 から Issue 7 まで。Issue 7 は [S1000D_DD_7](https://users.s1000d.org/S1000D_DD_7) | S1000D の公式サイト |
| [S1000D リファレンス（非公式）](https://shuji-bonji.github.io/s1000d-stack/ja/reference/s1000d/issue-7/) | 属性ごとの値の意味と、関連する決まり | 著者のサイト |
| [Stack リファレンス](https://shuji-bonji.github.io/s1000d-stack/ja/reference/stack/) | S1000D Stack のツールごとの引数と応答 | 著者のサイト |

正式な定義は、公式のデータ辞書と仕様書にあります。S1000D リファレンスは、値の意味を著者の言葉で説明した非公式の手引きです。本文では、属性名に S1000D リファレンスへのリンクを、ツール名に Stack リファレンスへのリンクを付けています。ツールは更新されることがあるため、本文にはツールの引数を書いていません。

同じデータ辞書は、仕様パッケージの Data Dictionary にも入っています。展開したフォルダーの `Index.html` をブラウザーで開くと、オンライン版と同じ画面を、自分のコンピューターで使えます。同梱の README は、自分のコンピューターで使うときは、ローカルの Web サーバーを立てるように案内しています（例: そのフォルダーで `python3 -m http.server` を実行し、`http://localhost:8000/Index.html` を開く）。

### 使うツール

確かめ方の例では、著者が提供している [S1000D Stack](https://github.com/shuji-bonji/s1000d-stack) の MCP サーバーを使います。LLM が S1000D のデータを正確に扱うためのツール群で、次の 4 つがあります。

| サーバー | 役割 |
| --- | --- |
| s1000d-reader-mcp | DM とパブリケーションモジュールを XML ではなく構造として読む |
| s1000d-verify-mcp | XSD の検証、BREX の検査、参照の確認、DML との照合 |
| s1000d-brex-mcp | BREX のルールの検査と、値の意味の検索 |
| s1000d-writer-mcp | DM を作る、直す、改版する |

MCP サーバーは、単独では動きません。MCP に対応した LLM のクライアント（Claude Desktop、Claude Code など）に登録し、LLM がツールを呼び出して使います。この本の例の結果は、LLM がツールを呼び出したときの応答から、要点を表にしたものです。LLM を使わずに試すときは、MCP の公式の確認用ツール（MCP Inspector）から、ツールを直接呼び出すこともできます。

S1000D Stack を使わなくても、この本は読めます。XML の例と決まりの説明は、S1000D Stack に依存していません。ほかの検証ツールを使う場合も確かめる観点は同じです。

:::message alert
この本の「確かめる」は、S1000D への準拠を判定するものではありません。XSD の検証と BREX の検査が通ることは、構造と、機械で判定できるルールに誤りが見つからなかった、という意味です。プロジェクトのビジネスルールに合っているかは人が確かめます。
:::

### この本の書き方

この本には、S1000D の仕様書の文章、XML スキーマ、公式サンプル（Bike Samples）の XML を載せていません。決まりは著者の言葉で書き、根拠として章と Para の番号を添えています。正確な内容は、お持ちの仕様書の同じ場所で確かめてください。公式サンプルについては、数えた件数だけを書くことがあります（例: 110 件のうち何件）。

## 対象の Issue

この本は S1000D Issue 7 を対象にします。要素名、属性名、章の番号、既定 BREX のルール番号は、Issue 7 のものです。ほかの Issue では名前も番号も違うことがあります。Issue による違いは、入門の「[版の違いと注意点](https://zenn.dev/shuji_bonji/books/s1000d-intro/viewer/issues-and-cautions)」で説明しています。

:::message
入門では、S1000D の仕様の版を「版」と書きました。この本では、仕様の版を「Issue」と書き、「版」は DM とパブリケーションモジュールの版（issue）だけに使います。
:::

## 深く扱わないこと

次の 2 つは深く扱いません。著者に実務経験が無いためです。

- 文章の書き方（Simplified Technical English など）
- 1 つの内容をどの大きさの DM に分けるか

## この章のポイント

- この本は、入門の続編で、DM を読み、確かめ、作るところまでを扱います。
- 例は著者が作った券売機のデータです。仕様書とスキーマと公式サンプルは載せていません。
- 必要なファイルは、仕様パッケージと実践データです。S1000D Stack を使うときは、MCP に対応した LLM のクライアントも要ります。
- 要素と属性の正式な定義は公式のデータ辞書に、値の意味とツールの引数は著者のサイトのリファレンスにあります。
- 対象は Issue 7 です。
