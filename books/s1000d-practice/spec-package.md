title: "仕様パッケージを用意する"

DM が S1000D の仕様どおりに書けているかは、XML スキーマ（XSD）と既定 BREX を基準にして確かめます。どちらも、S1000D のダウンロードサイトで配布されている仕様パッケージに入っています。この章では、パッケージを入手して、検証に使える状態にするまでを説明します。XSD と BREX がそれぞれ何を確かめ、DM とどうつながるかは「[DM と XSD・BREX の関係](https://zenn.dev/shuji_bonji/books/s1000d-practice/viewer/dm-xsd-brex)」で説明します。入手の手順そのものは、入門の「[入手方法と学習の進め方](https://zenn.dev/shuji_bonji/books/s1000d-intro/viewer/how-to-learn)」に書いています。

## スキーマと既定 BREX を各自で入手する理由

DM を XSD と既定 BREX で確かめるときは、使うツールにかかわらず、XSD と既定 BREX のファイルが必要です。XML エディターでスキーマ検証をするときも、自分で書いたスクリプトで検証するときも、この本で使う S1000D Stack で検証するときも、同じファイルを読み込みます。

ただし、この本にも S1000D Stack にも、これらのファイルは入れていません。S1000D の利用条件が再配布を認めていないためです。Issue 7 の仕様書の冒頭にある利用条件を、著者は次のように解釈しました。法的な判断ではなく、私的な要約です。

| 内容 | 著者の解釈 |
| --- | --- |
| 利用の許諾 | 条件を守る限り、利用することは認められている。再配布の権利は与えられていない |
| 対象 | 仕様書だけでなく、XML スキーマ、例（XML とスタイルシート）、ダウンロードページのほかの情報も含む |
| 改変 | 翻訳と翻案は認められていない。ビジネスルールを足すことは認められている |
| 再配布が認められる相手 | 維持団体の会員企業や、加盟国の国防省などに限られる。個人の開発者は含まれない |

そのため、XSD と既定 BREX は、各自でダウンロードサイトから入手してください。商用の CSDB 製品を使っている場合は、製品がスキーマを持っていることがあるので、製品の説明書で確かめてください。

S1000D Stack は、スキーマに似せた別のスキーマを作って配る方法も取っていません。検証には、読者が入手した本物のスキーマを使います。

## パッケージの中身

Issue 7 の仕様パッケージは、1 つの zip として配布されています。展開すると、仕様書の PDF が 1 つと、内側の zip が 10 本出てきます。内側の zip も含めて、すべて展開してください。

| 内側の zip | 中身 | この本で使うか |
| --- | --- | --- |
| XML Schema Package | XSD（`xml_schema_flat/` に 33 本。DM の種類ごとのスキーマと、それらが読み込む共通のスキーマ）、使える図の形式の一覧 | 使う（XSD で確かめる） |
| Default BREX | 既定 BREX の DM が 1 件 | 使う（BREX で確かめる） |
| Bike Samples | 自転車を題材にした公式サンプルの CSDB | 件数を数えるときだけ |
| Data Dictionary | 要素と属性の定義を引く画面（`Index.html`） | 調べるときに使う。中のスキーマは検証には使わない（XSD で確かめる） |
| Business Rules Template | ビジネスルール文書のひな形 | 使わない |
| Business Rules Decision Point Index | ビジネスルールの決定点の一覧（表計算のファイル） | 使わない |
| Example SNS | システムの番号の体系の例 | 使わない |
| Front Matter Samples | 表紙や目次などの例 | 使わない |
| Functionality Matrix | 機能マトリックス | 使わない |
| Unit of Measure | 単位の定義 | 使わない |

仕様書の PDF は 3,700 ページあります。章の番号で探せるように、自分のコンピューターで文章を検索できる状態にしておくと便利です。

## 置き場所を S1000D Stack に伝える

S1000D Stack の MCP サーバーには、パッケージを展開したフォルダーの場所を次のどちらかで伝えます。

| 方法 | 書くもの |
| --- | --- |
| 環境変数 | `S1000D_SPEC_DIR` に、展開したフォルダーの場所 |
| 設定ファイル | `~/.config/s1000d-stack/config.json` の `specDir` |

設定ファイルの例です。`csdbDirs` は、DM を置いたフォルダー（CSDB）の場所です。

```json
{
  "specDir": "/Users/you/specs/s1000d/issue-7",
  "csdbDirs": ["/Users/you/work/kenbaiki/csdb"]
}
```

環境変数と設定ファイルの両方があるときは環境変数が使われます。フォルダーの名前は自由です。サーバーは、指定したフォルダーの下から、既定 BREX とスキーマのフォルダーを探します。探し方は、「XSD で確かめる」と「BREX で確かめる」の「実装するときの注意」で説明します。

## 確かめ方

置き場所が正しく伝わったかは、s1000d-verify-mcp の [`list_schemas`](https://shuji-bonji.github.io/s1000d-stack/ja/reference/stack/verify/list-schemas/) で確かめられます。見つかったスキーマのフォルダー、その Issue、使えるスキーマの名前が返ります。

## 実装するときの注意

### 環境変数が届かない起動の仕方がある

デスクトップアプリからプラグインとして起動した MCP サーバーには、利用者が設定した環境変数が届かないことがあります。著者の環境では、`S1000D_SPEC_DIR` が届きませんでした。設定ファイルから読む方法を足したのはこのためです。ホームフォルダーの場所さえ分かれば、設定ファイルは読めます。

## この章のポイント

- XSD と既定 BREX は、DM が仕様どおりかを確かめる基準です。どちらも仕様パッケージに入っています。
- スキーマと既定 BREX は、利用条件のために自由に配れません。この本と S1000D Stack には入っていないので、各自で入手します。
- S1000D Stack には、パッケージを展開したフォルダーの場所を、環境変数か設定ファイルで伝えます。
