## 用語集

**適用（applicability）**
その情報がどの装備のどの構成に当てはまるかを、データとして持たせることです。公式の概要ページは、識別・状態の部分が適用を管理すると書いています。DM 全体にも、DM の中の段落やステップにも付けられます。条件の値は、ACT、CCT、PCT で管理します。

**ATA e-Business Program**
S1000D の三つのスポンサーの一つで、民間航空の情報交換の規格を担っています。公式サイトの外部リンクでは、Airlines for America（A4A）とは別に紹介されています。

**ATA Spec 1000BR**
S1000D を民間航空で使うためのビジネスルールです。S1000D そのものではありません。

**自転車サンプル（Bike sample data set）**
仕様のパッケージに含まれる、自転車を題材にした XML の例です。Issue 4.1 と Issue 5.0 の説明ページは、架空の製品であり、適合性の試験集ではないと書いています。Issue 6 と Issue 7 のパッケージにも含まれています。

**BREX（Business Rules Exchange）**
プロジェクトや組織のルールのうち、XML の構造の使い方に関するものを、機械で検査できる DM にしたものです。公式の概要ページは、DM の種類の一つに挙げています。情報コードは `022`、アイテムロケーションコードは `D` です。既定 BREX のシステム差分コードは、Issue 4.2 の複製では `F`、Issue 6 では `H`、Issue 7 では `J` です。

**ビジネスルール（business rules）**
仕様の枠の中で、プロジェクトが使う値、必須、禁止を決めたものです。人が読む文書と、BREX の両方で表します。BREX の検査の式にできない規則は、人が読む文書に残ります。

**BRDP（Business Rules Decision Point）**
仕様が、プロジェクトに決定を求めている点です。決めるべき点の一覧は、Issue 4.1 では Business Rule Decision Point index、Issue 5.0 では Project Decision Point Index という名前で同梱されています。Issue 6 では `S1000D Issue 6 BRDP Index.xlsx`、Issue 7 では `S1000D Issue 7 BRDP Index.xlsx` です。

**共通ソースデータベース（Common Source Data Base、CSDB）**
DM を保管し、管理する場所です。公式の概要ページは、その機能を定めていないと明記しています。Issue 7 の第4.2章も、設計と実装の規則は定めず、情報のデータ構造だけを定めると書いています。製品名ではありません。

**変更提案（Change Proposal Form、CPF）**
仕様を変更するための正式な手続きです。Steering Committee が審議し、受け入れられたものが新しい版に入ります。

**内容の部分（contents section）**
DM の二つの部分の一つで、利用者が作業するため、またはシステムを理解するために必要な情報そのものを書きます。公式の概要ページの用語です。

**データモジュール（Data Module、DM）**
独立した情報の単位です。公式の概要ページは、プラットフォーム、システム、構成品についての説明、手順、運用のデータを含むと書いています。Issue 7 の第1.2章は、技術刊行物の中で、それだけで完結する最小の情報の単位と定義しています。DMC を識別子として CSDB に保管し、取り出します。

**データモジュールコード（Data Module Code、DMC）**
DM を取り出すための識別コードです。「どの製品のどの部分か」を表す部分と、「どんな種類の情報か」を表す部分に分かれます。発行番号、作業中番号、言語は、DMC には含まれません。Issue 7 では、訓練用の DM に学習コードの区画が加わります。

**既定 BREX（default BREX）**
各版のパッケージに含まれる、仕様側の BREX です。プロジェクトの BREX とは別のものです。

**DIG（Defense Interest Group）**
防衛の顧客を代表する独立したグループです。スポンサーではありません。

**識別・状態の部分（identification and status section）**
DM の二つの部分の一つで、CSDB での管理、適用、品質保証、取り出しの制御のための情報を持ちます。公式の概要ページの用語です。XML の要素名は版によって変わります。

**IETP（Interactive Electronic Technical Publication）**
S1000D で、画面に対話的に表示する出版物を指す語です。紙や PDF と並ぶ出力の一つです。どの機能を持たせるかは、機能マトリックスとプロジェクトの要求で決まります。

**IETM（Interactive Electronic Technical Manual）**
主に米国の文書で使われる語です。米空軍の MIL-STD-3048A は、S1000D の IETP とほぼ同等と定義していますが、契約で求められる範囲は、この定義だけでは決まりません。米国 DoD のクラス（Class 0 から 5。IETM と呼べるのは Class 3 以上）は、『IETM入門 — 概念から S1000D まで』で説明しています。

**情報コード（information code）**
DMC の情報の部分にある、情報の種類を表す 3 文字のコードです。自転車サンプルの `041` は記述の DM、`022` は BREX、`024` は人が読むビジネスルールの DM です。全体の表は、各版の情報コードの章にあります。

**情報管理番号（Information Control Number、ICN）**
図など、DM とは別に CSDB で管理するものの識別番号です。Issue 7 の第4.4章は、CAGE コードを使う方法と、モデル識別コードを使う方法を説明しています。

**版（Issue）**
S1000D の版です。メジャー、マイナー、パッチの意味は、ダウンロードサイトが説明しています。メジャー版の間には後方互換がありません。版の識別には、仕様書の表紙の番号（“Issue No. 6”、“Issue No. 7” など）を使います。

**モデル識別コード（model identification code）**
DMC の先頭にある、どの製品またはプロジェクトかを表すコードです。自転車サンプルでは `S1000DBIKE` です。Issue 4.0 以降の属性名は `modelIdentCode`、Issue 3.0 以前の要素名は `modelic` です。

**パブリケーションモジュール（Publication Module、PM）**
DM などへの参照によって、出版物の内容と構造を定義するものです。記述の DM の一種ではありません。Issue 7 の第4.9章によると、識別子、状態、内容を持ち、内容は DM、従来の技術出版物、ほかの PM への参照です。Issue 4.0、Issue 6、Issue 7 のスキーマパッケージでは、`pm.xsd` が別のファイルです。

**Process データモジュール**
対話的な表示の中で、どの DM をどの条件で表示するかという流れを記述する DM の種類です。Issue 7 の `process.xsd` には、`dmSeq`、`dmIf`、`dmLoop`、`dialog` などの要素が定義されています。

**S シリーズ**
製品支援のための国際仕様のまとまりです。S1000D は技術出版物を担当します。S2000M、S3000L、S4000P、S5000F、S6000T は別の仕様で、SX000i は使い方のガイドです。

**S1000D Council**
ASD、AIA、ATA e-Business Program による、S1000D 全体を管理する組織です。将来の方向を示し、Steering Committee に方針を示します。

**S1000D Steering Committee**
CPF を審議し、仕様の新しい版を発行する、維持の責任者です。

**スキーマ（schema）**
その版の XML が従う構造の定義です。DM の種類ごとにファイルが分かれています。Issue 4.0 以降の名前の体系は、Issue 3.0 以前と互換がありません。

**標準番号体系（Standard Numbering System、SNS）**
製品を、システムからアセンブリまでの階層に分けて番号を付けるための枠です。番号の意味はプロジェクトが定義します。DMC のシステムの部分の中心です。

**システム差分コード（system difference code）**
同じモデル識別コードの中での違いを表すコードです。Issue 7 の第4.3章では、1 文字から 4 文字です。自転車サンプルは `AAA` です。

## 本書が結論を出していないこと

次の点は、確認した情報の範囲では結論を出していません。

- S1000D を採用すると費用が下がるかどうか。公式の利点のページは、可能性と、効果が要因によって変わることを書いています。
- 日本の公的機関が、S1000D を納品の仕様として採用しているかどうか。2022 年の調査研究の契約の記録以外に、採用を示す公式の発表は見つかりませんでした。
- 仕様本文と同梱ファイルの食い違い（BREX のアセンブリコード、Issue 7 のテンプレートの参照先など）のどちらが正しいか。詳しくは付録にまとめています。
- 特定の CSDB 製品、編集ソフト、ビューアの良し悪し。

## 作業を始める前に確認すること

契約を読み始めるときは、次の三つが決まっているかを確認してください。

1. 版（Issue）
2. ビジネスルール、または BREX
3. 納品する出力（紙、PDF、IETP と、機能マトリックスの範囲）

この三つがそろって、初めて要素名のレベルの作業に進めます。
